# 实测与已知边界

日期：2026-09-07。机器：**Apple M5 Pro，64 GB 统一内存，macOS 26.5.2，arm64**。参考是本人已有口播的 15 秒单人片段，仅在本机使用。公开仓库包含测试文案、样例代码和脱敏结果，不包含这段录音或克隆产物。

这不是跨设备排行榜。不同模型、暖缓存与句长影响时间；没有把单机短样本结果写成所有用户的实时或低内存保证。

## 三家音色对照与 MiniMax 默认

2026-09-07，声音本人在三段试听中都选择 **B = MiniMax**，并明确指定使用 MiniMax。默认后端与个人偏好据此更新；Qwen 保留为显式免费本地路线。这是个人实际偏好，不是供应商普遍质量排行榜。

三家使用同一段 12.05 秒本人录音。MiniMax 额外使用 4.05 秒精确转写 prompt，Qwen MLX 使用准确参考转写的完整 ICL。另取未参与克隆的三段原声，覆盖技术专名、口语问句、结尾节奏，用同样文案生成两轮，共 18 段；本地第二轮更换 seed，MiniMax 发起新请求但未控制 seed。全部结构校验通过，保留两轮完整结果。

试听副本仅做恒定增益调整（目标 -20 LUFS、峰值上限 -1 dBTP），不改速度或音高。页面可隐藏标签，但提交选择截图已揭晓，因此记录为用户试听选择，不声称双盲。

两个独立 WeSpeaker 编码器对合成段与**同文案未见原声**的余弦均值（3 段 × 2 轮）：

| 供应商 | ResNet34 | ECAPA512 | 用户首轮选择 |
|---|---:|---:|---:|
| MiniMax | 0.7912 | 0.8451 | 3 / 3 |
| Qwen3-TTS MLX | 0.8074 | 0.8486 | 0 / 3 |
| MOSS Nano | 0.6808 | 0.7407 | 0 / 3 |

**分数不是音色相似百分比。** MiniMax 与 Qwen 接近，Qwen 的两轮合并均值略高；MiniMax 没有获得客观指标的一致胜出。Nano 在本次样本的两个编码器上较低。原声三段之间的余弦范围分别为 0.8228–0.8618、0.8503–0.8943，内容和韵律也影响指标。与克隆输入本身的比较单列保存，不据此宣布胜者。

全部 18 段经同一 large-v3-turbo ASR 检查。MiniMax/Qwen 的差异主要是少量语气字和英文术语；原声 ASR 也会混淆这些术语，不能把转写偏差直接判为读错，没有据此改稿。样本同人同次录制、模型有限，没有人群校准、跨设备速度测试或受控双盲结论。

[完整脱敏数字与两轮分数](evidence/voice-provider-comparison.json)。参考音频、克隆输出、个人音色 ID 和账号信息留在本机。新增个人配置保存在技能目录外，升级不覆盖音色；默认 MiniMax，显式参数仍可切换后端。

实际修复了克隆登记的账号一致性问题：mmx 配置和环境变量可能属于不同账号，旧流程会分别用于上传与登记。现在两个请求使用同一凭据和区域，支持匹配 prompt；新音色已实际登记并完成上述合成。

方法来源：[MiniMax 复刻 API](https://platform.minimax.io/docs/api-reference/voice-cloning-clone)、[Qwen 音频与文本参考](https://github.com/QwenLM/Qwen3-TTS)、[WeSpeaker ONNX 预处理](https://github.com/wenet-e2e/wespeaker/blob/master/wespeaker/bin/infer_onnx.py)、[ResNet34 模型卡](https://huggingface.co/Wespeaker/wespeaker-voxceleb-resnet34-LM)、[ECAPA512 模型卡](https://huggingface.co/Wespeaker/wespeaker-ecapa-tdnn512-LM)。

新默认 Demo 不传 provider 或 voice 参数，读取个人偏好生成六句 MiniMax 配音：25.0678 秒，WAV/MP3/SRT 同源验证通过；六句 ASR 规范化文本均匹配。第二句改为供应商中性的表述，删去不再成立的“本地完成、无需在线套餐”，因此这支新 Demo 不作为同文案 A/B。

在新音频时轴上保留 21 拍动作。实际浏览器连续 127 次观测覆盖全部 21 拍，尾帧暂停；最大观测声画时钟差约 32.21 ms（非全帧上界）。1440×900 视口下舞台 x=80、y=90、1280×720，仍为 16:9；前进、回退、重播抽查通过，无页面错误。TypeScript/时轴检查 7 PASS / 0 SKIP，生产构建与现有网页测试通过；配音单元测试扩展到 23 项。[Demo 验收记录](evidence/minimax-demo-review.json)。

## Step 动画修订：保持同一配音与 SRT

本次修订回应“画面好看了，但长期停在同一构图”的实际反馈。前版固定为 `c99580a`；两版 WAV 和 SRT 逐文件 SHA 相同，时长都为 31.3535 秒。没有换语速或重做配音来遮住停滞。

| 同一口播区间 | 上一版的主要动作 | 本版可见推进 |
|---|---|---|
| 8.846–15.203 秒，时间戳 | 小时间轴出现，声音卡仍占主位 | 音轨全宽展开 → 六段拆开 → 标记依次落位 → 声轨/字幕轨对齐 |
| 15.203–22.096 秒，文字与关系 | 网页窗口入场后主要保持原构图 | 时间轴进入网页 → 文字长出卡片 → 连接与传递 → 中央主体前推 |
| 22.096–26.599 秒，同步播放 | 播放头和装饰曲线运动 | 文案、声音、画面依次前推，声音振幅/画面叠片跟随焦点变化 |

六段 SRT 内编排 **21 个动作拍**，来自同一份 beats.ts；动作谱也驱动 `?review=1&t=0&steps=1` 的静音逐步演示。原生点击实测全部 21 拍落点、上一步回退、重播；控件在内容框外。24 → 5 → 24 秒回查画面一致。减少动态效果时点击直接落位。普通手动模式超过首句时长仍保持在当前 Step，下一次点击才推进，修复了预览时钟继续触发未来动作的问题。

复查中还修了时间戳与标题间距、辅助时间轴的文字纵向压缩、stagger 最后一个对象在停拍时未完全落定三个问题。没有将循环闪烁或时钟刷新算成新增解释动作。

完整自动播放使用 mute=1 真实捕获跑完：1074 帧、402 次观测覆盖全部 21 拍，最大观测音频/场景时钟差约 **20.70 ms**，未捕获到运行时异常或音频错误。依真实内容框裁出 1280×720 MP4；这不是 60 fps 或跨浏览器流畅性保证。独立新目录通过实际 make-demo、`7 PASS / 0 SKIP` 与生产构建。导出后还用画面上的可见时钟复查，发现捕获帧存在约 100 ms 固定偏移；对两份原捕获做相同补偿，并排除起播蒙层帧。新版 MP4 的 17 / 20 / 24 / 26 秒抽查残差分别为 +50 / +40 / +70 / +40 ms；这与浏览器实时观测口径不同，不当作全帧误差上界。个人声音的前后视频、同步对比网页只在本机保存。

## 历史修订：Qwen 默认、16:9 外框与视觉样片

用户反馈后，默认模型改为 **Qwen3-TTS**，不再用 Nano 的 CPU 可运行性代替听感要求。Apple Silicon 自动选择 MLX，其他平台选择官方 PyTorch。`setup.py` 与 `run.py` 都使用同一默认选择函数；Nano 必须显式指定。

- 默认 setup 在本机解析为 mlx；不传 provider 的完整 run 实际生成了 31.3535 秒配音，synth 阶段约 7.8 秒（已有模型，不含安装/下载）。PCM 与前次已做 ASR 核对的 Qwen 样本逐文件一致。
- 新增平台路由测试，Python 测试合计 16 项。模拟平台测试不等于 Windows/CUDA 实机测试。
- 1920×1080、1440×900、2560×1080、480×270 四种窗口下，Manual/Auto/Review 三种模式均实际检查，共 12 个组合；矩形比例为 16:9，四周保留外边距，同视口切模式尺寸一致。1440×900 窗口里舞台为 1280×720，位置 x=80、y=90。[几何记录](evidence/revision-geometry.json)
- 舞台改为直角内容区；框线、角标和控制条在内容区外。录屏沿框线框选，不把浏览器外边距录入视频。
- 新样片全程实际捕获 1520 帧，336 次观测覆盖 step 0–5，最大音频/场景时钟差约 **19.15 ms**；最终音频 31.3535 秒，场景 31.354 秒（SRT 毫秒舍入），没有捕获到音频错误。按真实舞台裁出 1280×720 的本地 MP4 并查看视频帧。
- 24 秒 → 5 秒 → 24 秒的标题、对象样式和 MG 几何一致；系统减少动态效果时，24–25 秒装饰运动与主体变换保持稳定，功能性播放头继续跟随时间。[播放与验帧记录](evidence/revision-playback.json)
- 样片改用深色舞台、无衬线大字、分层文案/声音卡、真实配音振幅、SRT 片段和连续时间轴。固定主题不是所有未来项目的强制风格；视觉是否合用户偏好仍以实际样片反馈为准。
- 公共验收规则已覆盖 SKILL、EVALUATION、CRAFT、MOTION、脚手架提示及生成的 BRIEF，使用用户指定或本机可用的浏览器 skill，不限定 Ego。当前机器遵循本地偏好用 Ego 实测；并未声称已经逐一运行所有浏览器工具。

## 独立故障审查

独立前向审查使用正式安装在 site-packages 的 Nano 与真实模型，测试数据放独立目录。已发现并修复：

| 问题 | 修复后的实测行为 |
|---|---|
| 给 Nano 传了上游不存在的参数 | 固定 commit 的公共安装入口直接合成成功 |
| 修改原稿后旧交付仍能验证 | build、verify、网页 import 都拒绝旧清单 |
| WAV 头损坏导致恢复直接崩溃 | 自动重做损坏的 1 段，其他段保留 |
| 导入器接受被篡改的时长、缺 start、假 timing_method | 读取实际 PCM 帧并核验有限值、帧边界与方法，三种损坏均拒绝 |

此外已实际执行：不变输入全缓存、只改一段只重做该段、替换参考使全部失效、对真实生成进程发 SIGTERM 后断点恢复、整个产物目录搬迁、中文/空格路径导入。中断发生时缺失段阻止拼接；旧清单也不会冒充新稿成品。

仓库内 `python3 -m unittest discover -s tests -v` 首版包含 **15 项测试**，不用模型或云账号即可运行，覆盖文件/时间契约、文案保留、缓存失效与单句种子持久化。MiniMax 只核对当前 CLI help 和模拟 speech 调用参数，没有真的上传或消费云端额度；登记声音的 HTTP 流程尚未做线上验证。

## 网页交接与发行

六句样例通过实际 WAV 与 SRT 导入并生成时间轴，真实 TypeScript、时间轴/步数/前缀检查 **7 PASS / 0 SKIP**，生产构建完成。模板测试与 CI 不代替实际样例的画面验收。

Ego Lite 浏览器查了 7 个关键时间点并完成全片播放。第一次无捕获的后台测试出现最多约 0.98 秒画面采样滞后，不能当作流畅性通过。随后使用可见页面与真实 CDP 捕获会话重测：306 次观测覆盖 step 0–5，音频与画面最终同为 28.386 秒，观测到的最大时钟差为 **12.82 ms**，无音频错误；捕获 684 张帧。这个数是该次观测值，不能宣称所有浏览器“零漂移”或保证 60 fps。

画面复查还调整了输入卡片到网页窗口的空间关系，避免转场后克隆配音卡被遮住。README 图片来自最终场景。个人声音的预览 MP4 只在本机保留。

新增单句重试也经历独立复查：普通 synth 和完整 run 持久保留已选 seed 与音频 SHA；只有显式 clear 才恢复默认，避免已修读音在续跑时回退。

`npx skills` 的 local discovery 应恰好发现两个技能。发行验证使用隔离目录的 Codex/Claude Code 项目级 `--copy` 安装，不覆盖维护者已有的全局技能。参考声音、密钥、模型、字节码和个人路径在提交前检查排除。
